# Billing, credits and usage

Credits belong to the organization, not to one workspace. Every workspace in the organization spends from the same balance.

```bash
firstsales billing overview --org org_123 --json
firstsales billing credits --org org_123 --json
firstsales billing usage-summary --days 30 --org org_123 --json
firstsales billing credit-history --campaign-id camp_123 --limit 50 --org org_123 --json
firstsales billing payments --org org_123 --json
firstsales billing top-ups --org org_123 --json
firstsales usage get --days 7 --org org_123 --json
```

- `usage-summary` filters: `--days`, `--from`, `--to`.
- `credit-history` filters: `--limit`, `--offset`, `--from`, `--to`, `--action`, `--campaign-id`.
- `usage get` shows API calls, not credits.

## Paying (confirm first)

Neither command charges a card. Each returns a payment link. The user opens it and pays in their browser.

```bash
firstsales billing top-up --data '{"amountUsd":100}' --org org_123
firstsales billing checkout --data '{"returnPath":"/settings/billing"}' --org org_123
```

- `top-up` needs `amountUsd`, a whole number from 50 to 10000.
- `checkout` starts a plan purchase. Optional: `country`, `returnPath`, `amount`.
- Say the amount and get a yes before you make the link.

## Edge cases

- 403 `forbidden` on `top-up` or `checkout`: the API key lacks the `billing:write` scope. The user makes a key with that scope in the app.
- Signals refuse to run at zero credits. Check `billing credits` before a launch or a scan.
