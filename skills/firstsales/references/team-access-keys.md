# Account, team and API keys

An organization holds workspaces, members, billing and API keys. A workspace holds campaigns, contacts and the inbox.

```bash
firstsales whoami --json
firstsales doctor
firstsales orgs list --json
firstsales workspaces list --org org_123 --json
firstsales members list --search sam --org org_123 --json
firstsales teams members --org org_123 --workspace ws_123 --json
firstsales invitations list --status pending --org org_123 --json
firstsales groups list --org org_123 --json
firstsales domains list --org org_123 --json
firstsales api-keys list --org org_123 --json
```

- Start with `whoami`. It shows which user and organization the key belongs to.
- `doctor` checks the key, the base URL and the network in one go.
- `members list` filters: `--search`, `--page`, `--limit`.
- Workspaces have no limit. Do not tell the user they need a new plan to add one.

## Changes (confirm first)

```bash
firstsales invitations create --data '{"email":"sam@example.com","role":"member","workspaceScope":"all"}' --org org_123
firstsales groups create --data '{"name":"Sales","permissions":["campaign:launch"]}' --org org_123
firstsales domains add --data '{"domain":"example.com","maxRole":"member"}' --org org_123
```

- `invitations create` emails a real person. Show the address and role, then get a yes. Body: `email` required. Optional: `role` (`admin`, `manager`, `member` or `viewer`), `groupSlug`, `workspaceScope` (`all` or `specific`), `workspaceIds` (with `specific`).
- `groups create` needs `name` and `permissions` (at least one).
- `domains add` lets people with an email at that domain join the organization, up to `maxRole`. Body: `domain` required; `maxRole` or `maxRoleSlug` optional.
- `invitations cancel`, `groups delete`, `domains remove` and `api-keys revoke` all need `--confirm`. Ask first.

## API keys

- Never create an API key for the user. `api-keys create` prints the new secret, and you must never see it. Ask the user to make keys in the app, or to run the command themselves.
- `api-keys revoke --key key_123 --confirm` breaks anything that uses that key. Ask first, and never revoke the key this session runs on.
- Scopes limit what a key can do. A 403 with `API key scope insufficient` means the key lacks that scope.
- `accessLevel` is `workspace` (default) or `organization`.
